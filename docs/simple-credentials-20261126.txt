Password and login ID update — 2026-11-26

App passwords now accept 4–128 characters for student signup, teacher applications, manually created administrator accounts and teacher-issued student resets. Teacher/administrator IDs allow 4–20 ASCII letters, numbers or underscores, including numeric-only IDs and leading zeroes. Existing student Korean/numeric ID rules remain available.

Firebase email/password authentication itself requires at least six characters. The server represents only 4–5-character app passwords as Nsp1! followed by SHA-256 hex of a versioned, length-qualified input. The same function is used for signup, login and password resets. Passwords of six characters or more pass through unchanged, preserving existing credentials. This representation does not increase the entropy of short passwords. Existing server rate limits remain in place. App passwords and derived credentials are never persisted in D1 or logs; Firebase handles its normal password storage.

Short passwords should be set/reset in this app. Firebase Console password resets still follow Firebase's own minimum and use literal passwords of six characters or more; those continue to work in the app. A Firebase minimum-policy setting is not lowered or bypassed through its dashboard. No new key or secret is required and no existing account is reset by this deployment.

Validation: in-memory D1 with a stateful Firebase REST fixture that rejects native passwords shorter than six; numeric/leading-zero teacher ID, pending denial and post-approval login, student four-character signup/login, incorrect-password rejection, five-character reset plus numeric ID change, manually created administrator with four-character password, three-character rejection and legacy six-character credentials unchanged. Existing school/teacher isolation suites pass. See scripts/verify-simple-credentials.mjs.

No DB migration is required. R2 stays excluded. Production deployment uses GitHub main and Cloudflare automatic builds.
