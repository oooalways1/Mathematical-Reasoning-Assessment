# 학교별 관리·채점·학습 통합 변경 검토

작성일: 2026-10-19. 상태: 개발·로컬 검증, **운영 배포 승인 전**.

## 기준 소스와 보존

- 운영 Worker `math-literacy`의 100% 활성 버전 `1309141b`가 GitHub main의 `94aa5ad9bae34ee71d0c06e4b8775b129d802d33`을 가리키는 것을 Cloudflare 화면에서 확인했다.
- 이 커밋을 기준으로 별도 개발 체크아웃/브랜치 `development/school-integration-20261019`를 준비했다. 기존 작업 폴더를 초기화하지 않았다.
- 코드 백업과 운영 D1의 읽기 전용 SQL 백업을 별도로 저장했다. 학생 정보가 포함된 SQL은 Git에 포함하지 않는다.
- 백업의 11개 테이블, 기존 25개 행을 메모리 SQLite에 복원했다. 무결성·외래키 검사와 새 마이그레이션 적용 후 기존 행의 모든 값을 대조했다. 기존 학생 5명, 진단 2건 등 원본 행이 모두 유지됐다.
- 공개 중인 기존 공통 평가를 활성 학교 3곳에 복사하는 절차도 복원 환경에서 검증했다. 원본 평가/버전/답안은 유지한다.

학교 이동 전의 진단에는 당시 학교를 보존한다. 다른 학교 관리자가 이동한 학생의 과거 타 학교 기록을 받지 않도록 한다. 일반 학생은 자신의 학습 기록을 이어 볼 수 있다.

Google 로그인은 기존 Firebase UID와 서버 검증된 ID 토큰을 연결할 수 있는 구조를 마련했다. Google 팝업 로그인 버튼/제공자 활성화까지 완료한 것은 아니다. 관리자 초대 메일은 자동 발송하지 않는다.

## 검증 결과

- `npx tsc --noEmit --incremental false`: 통과.
- `node scripts/verify-evaluation-versions.mjs`: 평가 버전, 삭제/복구, 기록 보존, 연결형, 예시 채움 검증 통과.
- `node scripts/verify-school-management.mjs`: 학교 권한, 가입/기존 학생, 개인정보, 원자적 실패 처리 검증 통과.
- `node scripts/verify-school-integration.mjs`: 실제 API 핸들러와 전체 마이그레이션을 격리 SQLite에서 실행. 다른 학교 요청 차단, 관리자 발급/회수, 수동 재채점, AI 중복/오류/한도 대체, 20문항 묶음, 연습 이력, 비교 기준 해시 검증 통과. Firebase와 AI는 이 테스트에서 모의 응답을 사용한다.
- `node scripts/verify-ocr-files.mjs`: 실제 로컬 Tesseract로 빨강·파랑·검정 인쇄 답안, 한글 답 표시, 텍스트 PDF 검증 통과. 실제 아동 손글씨·촬영 품질 전체에 대한 정확도를 보장하는 시험은 아니다.
- `npm run build`: 빌드 통과.
- 실제 HTTP + 로컬 D1에서 학생 50명 × 20문항 동시 제출 50/50 성공. 측정 1,070ms, 중앙값 572ms, 95백분위 1,065ms. Cloudflare 운영 CPU 제한·외부 네트워크·Firebase 지연을 포함한 측정은 아니다.
- 브라우저 수동 확인: 학교별 평가 화면, 확인 필요 답을 교사가 정답으로 확정하여 83→100점 반영, 원본 답 보존, 6개 영역에서 이전 0%/최근 100% 그래프 표시.

## AI 모델과 무료 범위

Cloudflare 계정 화면에서 현재 Workers Free, Workers AI 일일 10,000 Neurons를 확인했다. 운영 Worker에는 아직 AI 바인딩을 추가하지 않았다.

| 후보 | 검토 |
|---|---|
| Qwen3 30B A3B FP8 | 다국어와 추론 지원, 비교적 낮은 토큰 비용으로 우선 선정. 실제 한국어 품질은 별도 가상 답안 검사 결과도 함께 판단 |
| Llama 3.3 70B FP8 fast | 유지 중인 대안. 크기가 크다는 사실만으로 한국어 교육 피드백의 우수성을 가정하지 않음 |
| Gemma 3 12B | 2026-05-30 지원 종료 목록에 있어 신규 기본 모델에서 제외 |

참고: [Qwen 모델](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/), [모델 지원 종료 공지](https://developers.cloudflare.com/changelog/post/2026-05-08-planned-model-deprecations/), [무료/과금 기준](https://developers.cloudflare.com/workers-ai/platform/pricing/).

설정은 두 단계다. 빌드 시 `NUMERACY_AI_BINDING=true`로 `AI` 바인딩을 포함하고, 런타임에 `AI_ENABLED=true`, `AI_FREE_PLAN_CONFIRMED=true`를 설정해야 호출된다. 외부 생성형 AI API 키는 필요 없다.

앱은 학생당 하루 최대 3회, 앱 전체 예약량 하루 9,000 Neurons, 요청당 200 Neurons 보수적 예약으로 제한한다. 예약량은 실제 청구 계측값이 아니다. 실제 수치는 Cloudflare 사용량이 기준이며 같은 계정의 다른 앱 사용량도 공유된다. 입력 9KB·출력 1,600토큰 제한을 적용한다. 무료 한도를 넘거나 AI가 실패해도 진단 저장과 채점은 유지된다. 유료 전환은 별도 승인 대상이다.

AI는 채점을 바꾸지 않는다. 문제 지문·그림이 부족한 경우 원인을 단정하지 않는다. 스키마·길이·기초 연산 표현 등을 검사해도 모든 수학적 오류를 자동 검증할 수 없으므로 교사 승인 전에는 학생에게 표시하지 않는다.

사용자 승인 후 실제 Playground에 가상 3문항을 보냈다. 첫 실행은 모델 표시가 바뀌었고, Qwen 선택 상태를 유지한 재실행에서도 글자/JSON이 중복 표시됐다. 이 화면 결과는 정상적인 앱 통합 성공으로 계산하지 않는다. API 호출에는 비스트리밍 JSON Schema를 지정하고 문자열/객체 응답 모두 검증하도록 보완했다. 이 옵션을 사용한 실제 바인딩 검증이 남아 있다.

## 남은 검증 및 배포 절차

1. 현재 Cloudflare의 main 이외 브랜치 빌드는 켜져 있지만 Worker Previews는 미설정이다. 프리뷰 기본 DB 바인딩/시크릿은 비어 있다. 저장소 빌드 설정에는 운영 D1 ID가 있으므로 **이 상태로 개발 브랜치를 원격 Push하지 않는다**. 코드에도 main 이외 CI 빌드 차단을 추가했다.
2. 별도 Worker `math-literacy-validation`을 생성하고 공개/프리뷰 URL을 모두 껐다. AI 바인딩만 연결했고, 운영 시크릿은 복사하지 않았다. 빈 D1 `numeracy-validation-db`도 생성했다. 전체 앱·마이그레이션 업로드는 Wrangler 권한 승인 후 진행한다. 검증 전용 세션 비밀값도 운영과 다르게 사용한다.
3. 실제 Workers AI 바인딩 호출 → 응답 검증 → D1 저장 → 교사 승인 → 학생 표시를 확인한다. Playground 품질 확인과 앱의 실제 바인딩 통합 검증은 구분한다.
4. 실제 Firebase 관리자 발급/로그인·즉시 권한 회수와 Cloudflare 무료 CPU 한도의 50명 시험을 격리 환경에서 추가 확인한다. 기존 학생 계정은 변경하지 않는다.
5. 실제 손글씨·스캔 PDF·다양한 촬영 샘플을 추가 확인한다. 연산 외 모든 주제에 3단계 새 문제가 준비된 것은 아니며 검증 자료가 없는 주제는 교사 준비로 표시한다.
6. 위 결과를 보고하고 **사용자의 최종 운영 승인 후** 최신 DB 백업을 다시 확보한다.
7. 승인된 마이그레이션 `0010_school_admin_grading_ai.sql`을 운영 D1에 먼저 적용한다. 테이블/학생 삭제나 초기화는 하지 않는다. 학교 범위 컬럼/지원 테이블/인덱스를 추가하고 당시 학교와 기존 활성 평가 복사본을 보존한다.
8. 새 총괄 계정으로 접근 가능 여부를 확인할 때까지 기존 관리자 로그인을 유지한다. 이후 main 반영·자동 배포·실제 운영 확인을 수행한다.

새 컬럼이 이미 런타임 초기화로 생긴 DB에 마이그레이션을 그대로 중복 적용하면 ALTER 충돌이 날 수 있으므로 적용 전 스키마와 마이그레이션 이력을 먼저 확인한다. 롤백 시 데이터/새 테이블은 삭제하지 않고 이전 Worker 버전으로 되돌리는 방식을 우선한다.

### 검증 빌드

`NUMERACY_DEPLOY_TARGET=preview`, `NUMERACY_PREVIEW_DATABASE_ID=<검증 DB UUID>`, `NUMERACY_AI_BINDING=true`를 지정한 빌드는 Worker 이름을 검증용으로 고정하고 운영 DB ID/임시 ID를 거부한다. 공개 URL도 비활성화한다. `scripts/verify-deployment-target.mjs`로 잘못된 대상의 빌드 차단을 확인했다. 검증 빌드의 실제 출력에도 별도 Worker/DB와 AI 바인딩만 포함됨을 확인한다.
