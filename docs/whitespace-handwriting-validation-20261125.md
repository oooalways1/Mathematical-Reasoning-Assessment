# 공백 채점 및 손글씨 PDF 검증 — 2026-11-25

## 변경 사항

- 정답과 제출 답안 양쪽의 공백, 줄바꿈, 탭, 전각 공백, 보이지 않는 간격 문자를 제거한 후 비교한다.
- 단답형, 선다형, 연결형, 선택지 묶음 및 기존 진단·연습문제의 정규화에 적용한다.
- 숫자 사이도 공백을 무시한다. 사용자 최신 지시에 따라 `1 2`와 `12`는 같다.
- 음수 부호, 소수점, 쉼표, 연산자와 순서에 따른 차이는 유지한다. 선택지 중복은 여전히 확인 대상이다.
- PDF 색상별 OCR에서 `6,10`/`6, 10`, `가나`/`가 나`처럼 공백만 다른 후보를 충돌로 처리하지 않는다. 실제 문자가 다른 후보는 계속 확인 대상으로 남긴다.
- 원본 제출 문자열을 저장하는 경로는 변경하지 않았다. 기존 평가 기록을 일괄 재채점하지 않는다.

## 손글씨 PDF 업로드 테스트

- 외부 API를 앱에 연결하지 않았다. 이미지 생성 도구로 검정·파랑·빨강 잉크의 가상 손글씨 20문항을 만든 뒤 ReportLab으로 이미지 전용 A4 PDF를 생성했다.
- 생성 요청: 한 열에 번호 1~20과 숫자·분수·소수·음수·계산식·한글 선택지 답안을 쓰는, 실제 인물·학생 정보가 없는 스캔 손글씨 답안지.
- 출력: `output/pdf/handwriting-answers-test-20261125.pdf`. PDF.js로 한 페이지와 선택 가능한 텍스트 없음 확인 후 PNG로 렌더링하여 시각 검수했다.
- 로컬 브라우저의 실제 파일 선택창으로 PDF를 선택했다. 앱 소스의 `readAnswerFiles`와 수정된 `scoreEvaluation`을 그대로 번들한 검증 화면을 사용했다. 운영 서비스 UI·DB 제출 테스트로 간주하지 않는다.
- 최초: 15문항에 답이 채워짐, 14문항 정답(70점). 공백만 다른 OCR 후보 때문에 3번·15번 답이 사라지는 문제 발견.
- 수정 후 동일 PDF 재업로드: 17문항에 답이 채워짐, 16문항 정답(80점).
- 남은 오류: 6번 `2`를 `그`로 오인식. 11번 `-3`/`=3`, 12번 `20`/`2.0`, 16번 `2`/`그` 후보 충돌로 비워짐. 정답 기준을 보고 OCR을 자동 보정하지 않았다.
- 원본대로 확인·수정한 기준 답안을 동일 엔진으로 채점하면 20/20, 100점.
- 단일 AI 생성 표본 결과이며 실제 학생 필기 전체의 정확도를 의미하지 않는다. 현재 손글씨 PDF는 인식 결과를 원본과 비교·수정하는 절차가 필요하다.
- 상세 원시 인식 결과는 로컬 `outputs/handwriting-upload-before-20261125.json`, `outputs/handwriting-upload-after-20261125.json`에 저장했다.
