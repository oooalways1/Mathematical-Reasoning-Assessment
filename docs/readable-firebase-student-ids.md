# Firebase에서도 읽을 수 있는 학생 아이디

2026-10-19 추가 요청. 상태: 로컬 구현·검증 완료, 이번 변경의 운영 배포 승인 전.

## 수정

- 한글·숫자·영문·밑줄·하이픈으로 만든 일반 아이디는 Firebase 이메일 식별자에도 그대로 넣는다. 예: 학생 입력 `민수` → Firebase `민수@students.soori-270e0.invalid`.
- Firebase 표시 이름에도 아이디를 저장한다. 학생은 계속 자기 아이디만 입력하며 이메일을 입력할 필요가 없다.
- 기존 영문 아이디와 실제 이메일로 가입한 계정은 그대로 유지한다.
- 이미 코드형 별칭으로 가입한 계정은 읽기 쉬운 주소와 이전 주소를 순서대로 인증한다. 올바른 비밀번호로 인증되고 기존 학생 프로필과 UID가 연결된 경우에만 서버 관리자 권한으로 같은 UID의 주소/표시 이름을 정리한다. 비밀번호와 학생/진단 기록은 바꾸지 않는다.
- 주소 충돌이나 프로필 동기화 실패가 있으면 기존 주소를 유지하고 정상 로그인을 계속 허용한다. 별칭으로 남아 있는 계정도 새 가입/학생 아이디 변경 시 중복으로 판단한다.
- 공백·이모지 등 이메일 주소에 직접 사용하기 어려운 형식은 기존 별칭 변환을 유지한다. `u-` 접두사는 기존 코드형 주소와의 충돌을 피하기 위해 예약한다.
- 기존 코드형 중복 조회 및 주소 정리는 이미 운영에 설정된 Firebase 서비스 계정을 사용한다. 새 API 키·유료 플랜·DB 마이그레이션은 필요 없다.

## 검증

- 실제 Firebase에서 한글 주소 직접 가입과 한글 표시 이름 저장을 확인했다. Firebase 콘솔의 식별자에도 한글 주소가 보이는 것을 확인하고 화면을 저장했다. 가상 계정은 삭제한다.
- 한글·긴 한글·숫자와 기존 아이디 복원/이메일 호환성 검사 통과.
- API 핸들러 회귀 검사: 읽기 쉬운 가입/표시 이름, 기존·신규 중복 차단, 코드형 계정 로그인, UID 유지 전환, 전환 서비스 실패 시 로그인 유지 통과.
- 실제 Firebase 가입·로그인과 메모리 학생 DB를 연결한 검사 통과. 이 검사에서 관리자 조회는 시험 응답을 사용했고 관리자 이메일 전환은 비밀키를 복사하지 않기 위해 실제 호출하지 않았다. 실제 운영 서비스 계정을 이용한 이전 계정 전환은 승인 후 가상 계정으로 최종 확인한다.
- 학교 관리/통합 검사와 TypeScript/빌드 검사 통과.

사용자 이메일 변경 시 본인 확인 메일이 필요한 프로젝트 설정은 유지한다. 서버 관리자 권한으로만 기존 코드형 계정의 주소를 변경하며, 이 설정을 끄지 않는다. [공식 계정 수정 API](https://docs.cloud.google.com/identity-platform/docs/reference/rest/v1/accounts/update).
