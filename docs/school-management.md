# 학교 목록과 학생 소속

- 관리자 → 학교 관리: 학교명과 지역을 등록·수정하고 신규 가입 목록에서 표시/숨김을 설정합니다. 동명 학교는 지역으로 구분합니다.
- 회원가입: 관리자가 등록한 활성 학교를 반드시 선택합니다. 학교가 없으면 등록 요청 안내를 표시합니다. 서버에서도 학교 ID와 활성 상태를 검증한 뒤 Firebase 계정을 생성합니다.
- 로그인: 기존 아이디와 비밀번호를 사용합니다. 저장된 학교가 로그인 후 화면, 진단, 학습 기록 및 인쇄 리포트에 표시됩니다. 학교 이름 변경은 다음 조회에 반영됩니다.
- 학생 관리: 학교/지역 표시, 학교별 필터, 학교명 검색, 학생별 학교 배정을 제공합니다. CSV에도 학교와 지역이 포함됩니다.
- 기존 학생은 학교 미지정으로 유지합니다. 관리자가 학생 관리 → 학교 배정에서 선택하면 기존 Firebase UID, 아이디, 진단과 학습 기록이 유지됩니다.
- 학교 숨김은 신규 가입과 신규 배정만 중지합니다. 기존 학생 로그인과 기록 조회는 계속 가능합니다. 실제 학교를 임의로 등록하지 않습니다.

## 저장과 배포

`schools`와 `student_schools`를 추가합니다. 기존 students 테이블을 변경하거나 데이터를 삭제하지 않습니다. 관계 테이블은 학생별 학교 한 곳을 보장합니다. 같은 학교명+지역의 중복 등록을 DB에서 차단합니다.

`drizzle/0007_school_directory.sql`은 반복 실행 가능한 마이그레이션입니다. 기존 Cloudflare 배포에서도 `app/api/_schools.ts`가 최초 학교 관련 요청 때 같은 CREATE IF NOT EXISTS 문장을 D1 batch로 실행하므로 별도 콘솔 SQL 작업 없이 적용됩니다. 초기화 실패는 다음 요청에서 재시도합니다. 가입 시 학생 정보와 학교 배정은 하나의 D1 트랜잭션으로 저장되며 실패 시 새로 만든 Firebase 계정만 정리합니다.

공개 `/api/schools`는 활성 학교의 ID/이름/지역만 반환합니다. 학생 수, 비활성 학교, 추가/수정, 학생 학교 배정은 교사 세션이 필요하고 쓰기에는 동일 출처 검사가 적용됩니다. 학생은 자신의 학교 정보를 조회만 할 수 있습니다. Firebase 설정이나 비밀 키 변경은 필요 없습니다.

학교 소속은 학생 프로필 정보이며, 학교별 교사 접근 권한을 분리하는 기능은 아닙니다. 현재 관리자 로그인 방식에 따라 교사는 전체 학교 학생을 관리합니다.

## 확인

`node scripts/verify-school-management.mjs`: 메모리 SQLite와 Firebase 모의 응답으로 권한 차단, 목록 노출 범위, 중복, 가입 검증, 트랜잭션 롤백, 기존 학생 배정, 숨김 이후 로그인/학교명 반영을 확인합니다. 운영 학생 계정에는 영향을 주지 않습니다.
