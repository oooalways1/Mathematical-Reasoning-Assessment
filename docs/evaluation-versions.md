# 평가 유형과 정답표 버전

## 교사 사용 순서

관리페이지 → 정답 설정에서 학년을 고르고 기존 평가를 누르면 수정할 수 있습니다. 문항 행을 펼쳐 내용/학습 주제, 평가 영역, 단답형/선택형, 보기 수(2~5개), 정답, 풀이 안내를 바꿉니다. 문항을 추가·삭제·이동할 수 있으며, 총 1~60문항을 지원합니다. 모든 문항은 동일 비중이고 점수는 100점 만점의 정수로 환산합니다.

새로운 검사지는 ‘빈 평가 만들기’ 또는 ‘기존 20문항으로 새 평가’를 누릅니다. 평가명과 같은 학년에서 중복되지 않는 유형 코드(A형, B형, 2026-2차 등)를 입력합니다. 기존 평가의 ‘다른 유형으로 복사’로도 만들 수 있습니다. 실제 검사지에도 평가명·유형 코드를 적어 학생이 올바른 평가를 선택하도록 안내합니다. 검사지 자체의 이미지나 PDF 문제를 편집하는 도구는 아니며, 종이 검사지를 기준으로 답안 형식·학습 주제·정답을 관리합니다.

- **비공개로 저장**: 작성 중 정답표를 보관합니다. 이미 공개한 평가를 비공개로 저장하면 신규 참여가 중지됩니다.
- **저장하고 학생에게 공개**: 모든 문항/정답과 확인 항목을 검증한 후 공개합니다.
- **평가 종료**: 학생의 새 참여를 중지하고 기존 기록을 보존합니다. 이후 수정·공개할 수 있습니다.

학생은 가입 학년의 공개 평가만 고를 수 있습니다. 선택한 평가의 문항 수와 답안 형식으로 직접 입력/파일 인식을 수행합니다. 답안지 인쇄에도 평가명·코드·기준 버전·문항 수가 표시됩니다. 새로운 평가를 선택하면 기존 입력을 지울지 확인합니다.

## 누적 기록

저장 때마다 새로운 정답표 버전을 만듭니다. 평가 이력/리포트/관리자 진단 기록/CSV에 평가명과 유형을 표시합니다. 원래 `assessments.key_version`을 변경 불가능한 평가 버전에 연결하고, 기존 답안·피드백 스냅샷을 유지합니다. 이후 수정은 이미 채점된 결과에 소급 적용되지 않습니다. 오답 반복 비교와 성장 그래프는 같은 학년·같은 정답표 버전만 비교합니다. CSV는 학생별 최근 결과 하나가 아닌 전체 진단 기록을 내보냅니다.

학생이 답을 입력하는 사이 평가가 수정·종료되면 제출을 거절하고 목록 재확인을 안내합니다. 정답표 갱신은 낙관적 버전 검사와 D1 트랜잭션으로 충돌을 감지합니다. 학생에게 전달되는 공개 평가 데이터에는 정답·풀이 안내·복습 정답이 포함되지 않습니다.

## 새 문항의 학습지원

기존 문항 구성으로 만든 평가에는 기존 관련 연습과 상황별 피드백이 연결됩니다. 문항 내용·영역·답안 형식이 변경되면 그 연결을 해제합니다. 새 문항은 등록된 주제·정오답·빈 답을 기준으로 기본 피드백을 제공하며 교사가 입력한 풀이 안내도 표시합니다. 새 문항의 별도 복습 문제/정답/힌트/해설을 등록하면 저장 당시 복습 문제로 학습을 이어 갑니다. 복습 문제를 등록하지 않으면 임의의 다른 문제를 배정하지 않고 미등록 안내를 표시합니다. 실시간 AI API는 사용하지 않습니다.

## 기존 DB와 배포

`drizzle/0008_evaluation_versions.sql`은 기존 테이블을 변경하지 않고 `evaluation_forms`, `evaluation_revisions`를 추가합니다. 기존 배포는 서버가 최초 관련 요청 때 동일한 CREATE IF NOT EXISTS SQL을 실행하고, 기존 학년별 정답표를 ‘기본형’으로 한 번 복사합니다. 정답표가 없는 학년은 문항 구성만 비공개로 준비합니다. 기존 기록의 버전을 찾을 수 없으면 ‘이전 평가 · 유형 미지정’으로 표시하고 추정하여 연결하지 않습니다. 기존 학년별 PUT API는 409로 새 편집기 사용을 안내하여 새 구조와 불일치하는 갱신을 막습니다. Firebase 설정 변경은 필요 없습니다.

평가 버전은 운영 화면에서 영구 삭제하지 않습니다. 평가 삭제를 누르면 학생의 참여 목록에서 숨겨지며, 삭제된 평가 보기에서 복구할 수 있습니다. 복구한 평가는 새 버전의 비공개 상태가 되므로 확인 후 다시 공개합니다. 삭제·복구해도 과거 결과는 당시 평가 이름과 기준으로 보존합니다. 학년이 다른 새 평가는 해당 학년을 선택해 만듭니다.

## 편집 화면 개선

문항 유형은 **선다형 / 단답형 / 연결형**입니다. 기존 선택형 데이터는 선다형으로 표시합니다. 연결형은 왼쪽과 오른쪽 항목을 각각 2~8개 등록하고 정답 드롭다운에서 한 번씩 연결합니다. 모든 연결이 맞을 때 정답 처리하며 부분 점수는 없습니다. 학생도 드롭다운으로 연결하고, 파일 답안은 `1-나,2-가` 형식으로 읽습니다. 연결 순서가 달라도 같은 연결이면 정답입니다. 답안지에는 연결 항목을 함께 인쇄합니다.

관리자는 평가 카드에서 문항·정답 수정과 평가 삭제를 고를 수 있고, 문항을 펼치지 않아도 행의 문항 삭제 버튼을 사용할 수 있습니다. 저장 전 문항 삭제는 현재 편집 중인 새 버전에만 반영됩니다. 학생 화면의 유형 코드는 **검사지 구분 이름 / 이름표**로 안내합니다. `첫 번째 검사`, `봄 검사` 같은 이름을 권장합니다.

**빈 문항만 예시로 채우기**는 내용·정답·안내가 모두 비어 있는 새 문항에만 작동합니다. 이미 입력한 실제 문항의 정답을 추측하지 않습니다. **전체를 예시 문항으로 구성**과 문항별 **예시 채우기**는 확인 후 일관된 예시 문제·정답·풀이·복습으로 바꿉니다. 제목과 구분 이름이 비어 있으면 연습용 이름을 채웁니다. 자동으로 공개하거나 정답 확인 항목을 체크하지 않습니다. 교사가 내용을 수정하고 실제 검사지와 대조한 뒤 공개합니다. 외부 AI API 호출은 없으며, 사전 작성 예시와 기기 내 계산으로 구성합니다.

`drizzle/0009_evaluation_trash.sql`은 평가 삭제 표시 테이블만 추가합니다. 서버에서도 동일한 반복 실행 가능한 SQL로 초기화합니다. 삭제된 평가가 같은 학년의 이름표를 계속 보유하므로, 같은 이름으로 새로 만들기보다는 복구하거나 다른 이름을 사용합니다.

검증: `node scripts/verify-evaluation-versions.mjs`는 메모리 SQLite에서 실제 마이그레이션을 적용한 뒤 A/B 분리 채점, 5지선다, 권한, 정답 비공개, 버전 충돌, 과거 기록 보존, 종료, 새 복습과 파일 답안 파싱을 확인합니다. 운영 DB나 Firebase 계정을 만들지 않습니다.
